# FROTH-RFC-0013: Prompt Context Architecture

**Status:** DRAFT
**Author:** Charlie (@charliebuddybot)
**Date:** 2026-03-25

## Problem

The current prompt context is a two-layer sandwich: one static lore
file (18KB, last updated March 20) and 200 raw messages. The lore
file contains stale claims, wrong hostnames, and historical events
that do not need to be in every prompt. The 200-message window
includes the bot's own narration noise. The Headlines pipeline
exists but is not wired into the prompt. The daily summaries (54
days, 560K chars) exist in the DB but are never seen — lore_file
mode replaces them with the static file.

## Proposed Layers

### 1. Foundation (~6KB, near-permanent)

Identity, personality, voice, operational rules, the vibe theory,
document formats, voice transcription registry. Updated monthly.
The parts of the lore that do not decay.

### 2. Headlines (~5KB, slow-decay)

One-line-per-day tabloid headlines covering day 1 through N-4
days ago. Uses the existing Headlines pipeline output. ~100
bytes/day instead of ~10K bytes/day. The fossil layer.

### 3. Full Summaries (~40KB, medium-decay)

The real daily summaries for the most recent N days (default 4).
Where the agent learns what actually changed in infrastructure,
relationships, and projects.

### 4. Recent Messages (fast-decay, filtered)

The raw message window, filtered:
- Strip the bot's own narration messages
- Strip cycle traces older than 2 hours
- Trim multi-page audit/dispatch messages to first paragraph
- Cap at 200 messages after filtering

### 5. Ephemeral State (regenerated per cycle)

Live infrastructure status, running tasks, actual hostnames,
pending Codex sessions, open threads. Generated by querying
the live system. The layer that prevents stale claims.

## Rendering Order

```
Foundation → Headlines → Full Summaries
  [page break]
Chat Context
  [page break]
Ephemeral State
  [page break]
Recent Messages
```

Each layer boundary is a page break for prompt caching.
Foundation + Headlines are cache-stable across hours. Full
Summaries are cache-stable across a day. Only Ephemeral State
and Recent Messages change per cycle.

## Implementation

Modify `BotContext.build/2` to accept a list of context layer
modules instead of the binary `lore_file`-or-summaries switch.
Each layer implements a `render(chat_id, opts)` callback
returning a `%Context{}` fragment. Layer modules:

- `Froth.Telegram.ContextLayers.Foundation`
- `Froth.Telegram.ContextLayers.Headlines`
- `Froth.Telegram.ContextLayers.Summaries`
- `Froth.Telegram.ContextLayers.Messages`
- `Froth.Telegram.ContextLayers.Ephemeral`

The Foundation layer reads a static file. The Headlines layer
queries the headlines table. The Summaries layer queries the
last N chat_summaries. The Messages layer does what it does
now but with a filter pipeline. The Ephemeral layer runs live
queries against running processes, tasks, and infrastructure.

## Cost Impact

Current: ~18KB lore + ~200 messages ≈ ~150-200K input tokens.
Proposed: ~6KB + ~5KB + ~40KB + ephemeral + filtered messages.
Slightly larger in raw bytes but cache hit rate increases
significantly. Foundation and Headlines are perfectly cacheable.
Net cost per cycle should decrease.
